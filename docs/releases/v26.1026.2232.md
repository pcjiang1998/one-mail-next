# OneMail Next v26.1026.2232

发布日期：2026-10-26。应用版本：`26.1026.2232`。发布标签：`v26.1026.2232`。升级基线：`v26.1026.1352`（`835ccb9`）。

本版汇总 `v26.1026.1352` 之后的全部应用改动：`ad4dd589ca2d50274b9cecd3b6ecd288e4d4ea9b` 的同步范围与缓存功能，以及本次发布提交中的数据一致性、安全边界和手动更新流程修复。旧版本已经发布的功能不重复计为新增；低影响的未处理事项不列为已修复。

## 中文

### 邮件同步范围与缓存

- 新增“设置 > 邮件同步范围”，独立配置邮件元信息、全文和本地缓存保留天数。默认值分别为 30、7、0 天；元信息最多 90 天，全文最多 30 天，元信息范围必须大于全文范围，非零缓存保留天数必须大于元信息范围。
- 输入失焦或保存时进行整体校验，非法值恢复为当前字段最近一次合法值，不重置其他字段。保留天数为 0 时不清理缓存，手动清理按钮也不可用。
- IMAP 与 POP3 按邮件日期和本地缓存完整性补齐元信息、正文及附件，不按已读或未读区分。改进 IMAP 邮件头、BODYSTRUCTURE、正文分段与 MIME 参数处理；POP3 尽量先取邮件头，必须取得整封邮件时保留并复用额外内容。
- 附件默认随正文缓存，也可启用“附件单独下载”。该策略在首次获取邮件元信息时保存到邮件记录，切换后不追溯修改已有邮件，不在后台重拉已缓存正文来补附件。已缓存附件显示“保存（已缓存）”。
- 启动时及每 24 小时检查过期缓存，也可手动清理。过期基准采用邮件日期与最近用户访问时间的较新值，保护刚打开的旧邮件；所有仍关联看板的邮件，以及仍被草稿、发送、规则、写回等任务使用的邮件均受保护。
- 默认仅清理过期正文和附件内容；显式启用元信息清理后才删除对应本地元信息。清理和同步范围调整不会触发服务器邮件删除或移动，也不会删除用户另存到其他目录的附件。

### 数据一致性与可靠性

1. **数据库恢复与在途任务隔离。** 正文、附件、同步、发送、规则、邮箱监听和 IPC 任务尚未结束时，明确拒绝恢复，等待完成后可重试，避免旧请求写入恢复后的数据库。恢复成功后重建邮箱监听、提醒及相关通知回调。
2. **MOVE 后维护正确身份。** 移入已删除或从已删除恢复后保存目标文件夹与新 UID，更新搜索索引和两侧计数。服务器不返回 COPYUID 时，以唯一且精确匹配的 Message-ID 确认目标；不能确认时明确报告定位未确认，不再继续使用旧 UID。
3. **普通同步及时识别远端缺失。** refresh 使用完整 UID 集合核对缺失，而不是把日期窗口之外未返回的邮件误判为删除。缺失只影响远端可用性，本地副本继续保留。
4. **旧快照不覆盖新操作。** 增加状态修订号，对同步请求前后的状态进行核对，防止旧 flags 或邮件头覆盖新的已读、已回复、隐藏、恢复、移动和永久删除结果，避免本地条目重新出现。
5. **区分 SMTP 失败与投递未知。** 明确拒收仍按普通失败处理；已经开始投递但最终结果无法确认时，显示“投递结果未知”，阻止发送队列重试、复用原记录重发或通过草稿绕过限制，降低重复投递风险。SMTP 已明确成功后的本地记账或已发送追加警告不触发重发。
6. **账号修改原子提交。** 先完成远端文件夹发现和校验，再统一提交账号字段、密码、IDLE 能力与文件夹选择；远端 LIST 失败或本地事务失败不会留下半套新配置。
7. **新邮件规则可靠登记。** 邮件入库与规则执行登记位于同一事务，登记失败则回滚，不再依赖同步结束后的时间戳扫描；移除超过 1000 封时整批漏登记的限制。初次同步、历史回填及 UIDVALIDITY 重置仍不批量执行历史邮件规则。

### IPC、附件与备份边界

- 所有 invoke IPC 校验调用页面为可信应用主 frame，开发与打包环境分别核验来源，避免任意页面直接调用应用接口。
- 附件路径按窗口和当前数据库记录原生文件选择授权，发送及保存草稿均校验；合法持久草稿可在重启后继续使用已有附件，恢复数据库后旧选择授权失效。保留 25 MiB 附件总大小限制。
- SQL 恢复显式禁止 `VACUUM`，包括 `VACUUM INTO`、指定数据库及 EXPLAIN 变体，阻止这类额外文件写入。该限制不代表 SQL 备份已成为可信或完全沙箱化的输入，仍应只导入可信备份。

### 检查更新与手动下载

- 手动和定时检查统一使用实际下载安装的更新器，并明确关闭自动下载。发现新版仅通过更新行下方的小字显示“发现新版本 v{version}”，按钮从“检查更新”切换为“下载更新”；当前版本号不再作为额外的新版本提示。
- 点击“下载更新”后才开始下载，显示进度条、百分比、已下载大小、总大小和速度。准备阶段显示“正在准备下载...”，完成后提供“重启更新”。
- 检查失败显示“检查更新失败”，下载失败显示“下载更新失败”并可重试。移除独立 GitHub 标签查询覆盖更新器失败状态的路径，后续成功的后台检查也不再被旧的本地错误提示遮挡。
- 下载期间禁用重复操作；定时检查不会覆盖下载中、已下载或安装中的状态。同一实例不会重复启动同一下载，完整有效缓存可复用。
- Windows 安装包缓存在 `%LOCALAPPDATA%\one-mail-next-updater\pending`，不写入系统“下载”文件夹。根目录还可能保留差分更新所需的 `installer.exe`，下载中可能有临时文件和 blockmap，因此缓存可能超过一个安装包大小，但不会按点击次数不断新增副本。失败或损坏的缓存可能需要重新下载，不承诺所有场景均可断点续传。
- 纯 `--dir` 解包构建不保证生成自动更新配置；需要自动更新时使用正式安装版。旧版应用的更新行为仍由旧代码决定，必要时可直接从本 Release 附件手动安装本版。

### 升级注意事项

- 首次启动自动迁移同步设置、附件缓存、最近访问时间、同步回填和状态修订号等数据。旧 `syncWindowDays` 用于元信息范围：0 转为 90 天，其他有效整数限制在 8 至 90 天；全文初始化为 7 天，缓存保留初始化为 0。迁移不删除现有缓存。
- 增加持久化的 `delivery_uncertain`。旧版失败发送记录缺少可靠的投递阶段信息，升级时保守标记为结果未知；启动或恢复时遇到中断的 sending 记录也采用该标记。**请先核对收件方或已发送邮件，不要直接重发未知结果记录。**
- 建议升级前备份数据库及重要附件。SQL 备份不包含磁盘附件文件，且包含敏感凭据材料；恢复替换当前数据库，不执行合并。迁移后的旧版本回退未验证，应保留升级前备份。
- 本版没有修复 Gmail / Outlook 重连或 OAuth 刷新，没有统一全部远程内容与 OAuth 请求的账号代理覆盖，也未改变本地数据库和备份的既有加密边界。
- 第三方 favicon 域名请求、遗留删除同步配置和部分既有界面的英文覆盖仍保持原状；当前 IMAP 会话仍不支持 UID 定向永久删除，相关操作会拒绝执行，恢复及规则移动仍要求服务器支持 MOVE。

## English

Release date: October 26, 2026. Application version: `26.1026.2232`. Tag: `v26.1026.2232`. Upgrade baseline: `v26.1026.1352` (`835ccb9`).

This release combines the sync-range/cache work in `ad4dd589ca2d50274b9cecd3b6ecd288e4d4ea9b` with the reliability, security-boundary, and explicit-update-download changes in this release commit. Previously released features and deferred low-impact findings are not counted as new fixes.

### Sync Ranges and Local Cache

- Added Settings > Mail Sync Ranges with independent metadata, full-message, and retention windows, defaulting to 30, 7, and 0 days. Metadata is limited to 90 days and bodies to 30 days; metadata must exceed the body window, and nonzero retention must exceed metadata.
- Validate the complete range configuration on blur/save, restoring only the edited field's most recent valid value on failure. Retention of 0 disables both scheduled and manual cleanup.
- IMAP and POP3 backfill by message date and cache completeness regardless of read state. Improved IMAP headers, BODYSTRUCTURE, body sections, and MIME parameters. POP3 uses headers when possible and retains extra content when the protocol requires downloading a complete message.
- Attachments cache with bodies by default. Separate-download policy is captured when metadata is first fetched; changing it does not rewrite existing policy or redownload cached bodies to fill attachments. Cached attachments are labeled Save (cached).
- Retention checks run at startup and every 24 hours, with manual cleanup available. Expiry uses the later of message date and last user access. Board-linked mail and messages used by drafts, sends, rules, or writebacks remain protected.
- Default cleanup removes expired bodies and attachment content only; metadata deletion requires explicit opt-in. Neither cleanup nor range changes delete or move server messages or remove separately saved files.

### Reliability and Security

- Reject database restore while asynchronous mail/settings tasks are in flight; rebuild mailbox watchers, reminders, and notification callbacks after successful restore.
- Preserve destination folder and UID after MOVE, update indexes/counts, and resolve missing COPYUID using a unique exact Message-ID match. Unconfirmed destinations are reported explicitly rather than continuing with obsolete identity.
- Detect routine remote disappearance using the complete UID set without mistaking messages outside the date window for deleted mail. Local copies remain available.
- Use state revisions to prevent stale flags/headers from overwriting newer read, answered, hidden, restored, moved, or permanently deleted state.
- Distinguish definite SMTP rejection from uncertain delivery. Block retries or draft/send bypasses for uncertain records; successful-delivery bookkeeping or Sent-append warnings do not cause resending.
- Discover/validate remote folders before atomically committing account fields, credentials, IDLE capability, and folder selection.
- Register new-mail rule execution in the message-insert transaction, removing the 1,000-message limit and the post-commit timestamp gap. Initial sync and historical backfill still skip historical rules.
- Validate trusted application main frames for invoke IPC. Authorize local attachment paths against native selection or persisted drafts, retaining the 25 MiB total limit and invalidating old selections after restore.
- Reject VACUUM statements during SQL restore, including file-writing variants. This is not a general-purpose SQL sandbox or proof that untrusted backups are safe.

### Explicit Update Downloads

- Update checks now use one authoritative updater with `autoDownload = false`. A successful newer-version result appears in the small status text and switches Check updates to Download update, without highlighting the installed version.
- Download starts only on request, with a progress bar, percentage, transferred/total size, and speed. Completion offers Restart to update.
- Check failures and download failures have distinct plain status messages; downloads can be retried. Removed the independent GitHub-tag lookup that could overwrite updater errors, and let later successful checks replace stale local errors.
- Prevent duplicate in-flight downloads and preserve downloading/downloaded/installing state during scheduled checks. Valid complete downloads reuse the existing updater cache.
- Windows packages are cached under `%LOCALAPPDATA%\one-mail-next-updater\pending`, not the Downloads folder. A base `installer.exe`, temporary files, and blockmaps may also consume space; clicking repeatedly does not create unlimited copies. Interrupted/corrupt downloads may require retransmission, and universal resume support is not promised.
- Use installed distributions for automatic updates; pure directory builds may lack updater configuration. Older installed versions still use their old update logic, so install this release manually from its assets if necessary.

### Upgrade and Compatibility

- First launch migrates sync settings, attachment/body cache fields, access timestamps, backfill markers, and state revisions without deleting existing cache. Legacy `syncWindowDays = 0` becomes 90 metadata days; other valid integers are clamped to 8-90. Body range starts at 7 and retention at 0.
- Adds persistent delivery-uncertain state. Previously failed sends lack reliable delivery-stage information and are conservatively marked uncertain; interrupted sending records are also marked uncertain on startup/restore. **Verify delivery before resending.**
- Back up the database and important attachment files before upgrading. SQL backups contain sensitive credential material, omit disk attachment files, and replace rather than merge the current database. Downgrade compatibility after migration is unverified.
- Gmail/Outlook reconnection, OAuth refresh, complete account-proxy coverage, local encryption boundaries, third-party favicon requests, legacy delete-sync fields, and incomplete existing English UI coverage are unchanged.
- UID-scoped IMAP permanent deletion remains unsupported and rejected; restore/rule moves require server MOVE support. Existing platform signing requirements still apply.

### Verification and Packages

- Passed **386 tests in 67 files**, Node/Web type checks, production builds, changed-file ESLint with no errors/warnings, and whitespace checks.
- Isolated Playwright checks at 1280×900 and 375×812 covered discovery, explicit download/progress, completion, and failure with no button overflow, out-of-window progress, or page errors.
- Tests did not use real mailboxes, send mail, download/install real updates, modify user databases, or clean user caches. Live failure interleavings and installed-package smoke tests on every platform remain unverified.
- Seven pre-existing repository lint errors and formatting warnings remain; this is not a claim of a clean whole-repository lint run.
- The tag workflow builds Windows x64/ARM64 installers, macOS x64/ARM64 DMG/ZIP, and Linux x64/ARM64 AppImage/DEB with update metadata. Actual package availability and cloud results are determined by this release's assets and Actions runs.
